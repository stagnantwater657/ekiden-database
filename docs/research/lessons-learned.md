# 每批复盘与规则改进

## 责任与流程

研究执行者负责事实、日志和差异报告；独立复核者负责重新检索关键证据、检查数据/日志覆盖；仓库维护者在 PR 评审后决定是否接受规则变更。独立复核者应与原研究执行者不同，可是另一位研究者或维护者，但不允许同一执行者自称已完成独立审核。CI 成功不是研究批准，本规范不额外赋予合并或部署权限。

**执行者发现问题 → 提出规则修改 → 独立评审 → 更新 Playbook → 更新回归案例 → 后续批次应用。**

规则修改在 PR 中列出：问题与来源、原规则、拟改规则、影响范围、是否改变证据门槛、反例及回归验证方式；重大修改单列，不藏在数据更新里。执行者可在独立分支准备完整可评审补丁，批准前仍采用既有证据标准，不以待批准规则放行数据。禁止自行降低门槛、删除失败案例或降低验证要求。

评审结论链接到具体 PR review/commit，未经评审只标 proposed；通过后记录 accepted 和适用批次，不追改旧日志使其看似满足新规则。一次性异常先作为局限/案例，至少说明适用条件才推广成通用规则。没有新建议可以报告“本轮无新增规则”，不强制每批改规范。

## 批次结束模板

- 批次/提交/执行者：
- 新增、修改事实：逐字段数量和稳定 ID；与生产 diff 对应的日志：
- 未核实字段：candidate / not-found / conflict 分别列出、原因、下一步；verified-absent 另列肯定证据：
- 检索问题：不可访问、历史栏目遗漏、来源冲突、项目/日期/身份问题：
- 现有数据错误：旧值、新候选、影响、来源；未经授权不顺手修改其他分支：
- 规则建议：无新增规则 / proposed（原因、改动、影响与反例）：
- 回归评估：适用 R1–R8 的独立实际检索结果及日志，未运行明确写未运行：
- 校验结果与保证边界：
- 独立复核者及评审链接：待评审 / 实际链接，不伪造审批：
