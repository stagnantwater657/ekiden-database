# 资料档案与赛事成绩界面

本轮基于 PR #14 合并后的 `2307335`，把详情页从通用查询表单拆为独立档案与成绩页。既有 Repository、实体 ID、查询解析与排序逻辑继续使用。

## 页面分工

| 路由 | 内容与交互 |
| --- | --- |
| `/` | 年鉴入口、实际数据库统计、三大驿传入口与最近比赛 |
| `/athletes/[id]` | 历史大学关系、资料空缺提示、PB 预留，以及按箱根／全日本／出云分组的全部参赛记录 |
| `/universities/[id]` | 已收录届次中的综合表现、三大赛事概况与历史选手 |
| `/races/[id]` | 有来源的赛事基本资料、最新已核验路线、待核实的正式区间纪录、优胜校与历届档案 |
| `/editions/[id]?section=6` | 第六区官方区间成绩及可核验的累计数据；省略参数默认第一区 |
| `/editions/[id]?section=final` | 正式综合成绩；参考队与失格、退赛等状态单列；箱根另列已有官方往返路用时 |
| `/results` | 原有跨赛事、赛季、年份、大学、队伍、区间及选手筛选，区间／大学视图、手动排序和分页 |

各详情页保留原路径和稳定 ID。独立档案不再显示通用筛选控件；进一步筛选通过有作用域的高级检索链接进入 `/results`。届次页的 `section` 参数可刷新、分享和前进后退。旧详情页链接即使带有通用查询参数仍能打开对应档案；高级查询状态应使用 `/results`。

页面和表格均为服务器组件；区间切换使用普通 Next.js 链接，没有额外客户端状态仓库。表格在自身容器内横向滚动，页面在手机宽度下不产生整页横向溢出。

## 视觉规范

`app/globals.css` 统一维护纸色背景、白色内容、深色文字、品牌红、转播面板、纪录金及升降色。档案页采用紧凑排版与细分隔线；深色只用于赛事顶部和首页收录统计。成绩与顺位使用等宽数字。

- 区間賞：品牌红底白字。
- 区間新：纪录金底黑字；可与区間賞并列。
- 上升为绿、下降为红、不变或无比较值为灰色短横线。第一区无上一棒可比较。
- 所有徽章来自明确的官方认定，不由本站最快时间或个人 PB 推断。

## 累计数据与资料边界

详见 [累计成绩来源与计算](scoreboard-sources.md)。2024 第 56 回全日本新增独立的展示补充资料，保存官方 27 队 × 8 区累计时间及正式队累计顺位；按既有 `resultId` 关联，原始区间成绩不变。

普通完整的全日本／出云比赛，只有正式队伍均完赛、所有区间用时完整且与官方总用时逐队一致时，才允许按区间累加。页面明确写“按区间用时计算”，相关排名是计算值，不冒充官方通過順位。箱根、存在特殊结果或资料不全的比赛不套用该计算。参考队不获派生综合排名。

领先差由本区间结束后的累计用时减去同一届同一区间正式领先队的累计用时；顺位变化为上一棒累计顺位减去当前累计顺位。最终综合差距使用官方总用时。参考及特殊状态不产生虚构的正式排名或冠军差。

当前官方区間賞／区間新核验仅覆盖第 56 回全日本（8 项／2 项）；其他届次未标记不意味着没有获奖或纪录。赛事总览的历史区间纪录仍须按最新路线版本另行核实，不把 11 届样本最小值作为纪录。出身高中、当前实业团及个人 PB 等未知资料保持空白；历史代表大学不能覆盖当前归属。

## 数据保护与扩展

本轮不修改 `data/editions/`、Registry、Manifest、身份决策、导入计划或已有数据来源。全库维持 11 届、2030 条区间参赛记录、990 位选手、63 所大学。新展示资料放在 `data/presentation/`，均保留独立来源定位；没有新增或重新生成选手 ID。

`lib/profiles.ts`、`lib/race-profile.ts` 与 `lib/scoreboard.ts` 是只读展示投影，未更改导入器、Repository 筛选／排序语义或生产服务。未来 PB、官方区间纪录和累计资料必须先核验来源及路线版本，再补充结构化资料。

GitHub Actions、Dockerfile、Docker Compose、SSH、sudoers、BuildKit 和部署授权机制均保持不变。仅创建 PR，不触发部署。
