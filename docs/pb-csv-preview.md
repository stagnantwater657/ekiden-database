# CSV → PB 比较与审核（MVP）

本工具仅比较本地 CSV 与当前仓库已发布的 PB 快照。始终 dry-run，不联网、不创建选手、不写生产资料或研究日志、不认定 verified。更快的输入不是“截至研究日的最新 PB”的证明。人工审核后正式导入的流程不属于本工具。

## 运行

使用项目要求的 Node.js 24，先执行 `npm ci`。

```bash
npm run pb:preview -- --input examples/pb-preview.csv --as-of 2026-11-23 --out /tmp/ekiden-pb-review-demo
```

`--input`、`--as-of`、`--out` 均必填；顺序不限。不支持 `--write` 或其他写入生产数据选项。截止日期须为有效 ISO 日期，不隐式取当前时间。

输出目录必须尚不存在，且父目录已存在。已有目录、文件或符号链接一律拒绝，避免覆盖旧审核。重新执行请指定另一个新目录；磁盘写入失败可能留下部分报告，应保留并检查，不会自动清理用户文件。

示例 CSV 中的 athleteId/姓名/大学取自注册表，但所有输入成绩、日期、赛事都是**合成演示，不是真实事实**。`example.org` 是格式占位地址，会被标记为来源不足，不得拿示例当导入依据。演示比较结果随本地 PB 快照变化。

命令成功生成报告时退出码为 0，即使报告内有 invalid/identity-conflict；0 不代表可发布。参数、CSV 结构、编码、数据库校验或文件写入错误时退出码为 1，不生成完整审核结果。

## CSV 约定

UTF-8（可有 BOM），逗号分隔；必须包含且仅包含下列八列，可调整列顺序。支持 LF/CRLF、双引号包裹字段、字段内逗号/换行及 `""` 转义。不猜测分号分隔或 Shift-JIS；请先自行转换。空白物理行可忽略，列数错误或损坏引号会拒绝整份 CSV，不能静默漏行。

| 列 | 规则 |
| --- | --- |
| athleteId | 已公开稳定 ID；缺失时仅给姓名候选，不能自动匹配 |
| name | 与 ID 的注册姓名或已确认别名交叉核对 |
| university | 大学 ID、注册名称或队伍名称；兼容名称末尾“大学/大” |
| event | `5000m`、`10000m`、`half-marathon` |
| time | `M:SS`、`H:MM:SS`，可带两位小数 `.cc`；如 `28:07.63`、`1:00:13` |
| date | `YYYY-MM-DD`；真实日历日期，不能晚于 `--as-of` |
| meet | 赛事名称；空白列为待补证据 |
| sourceUrl | 公开 HTTP(S) 来源地址；允许正常结果查询参数，拒绝凭证和占位域名；不会访问地址 |

时间复用研究审计的标准化解析语法。整数毫秒与 `second`/`centisecond` 精度同时保留：`14:00` 与 `14:00.00` 数值相同但精度不同。禁止零、负数、秒/分钟溢出、非安全整数、三位或一位小数；不四舍五入或猜测时间。原始字段也保留在 JSON。

空日期或来源为 `needs-evidence`；非空非法日期/时间/项目为 `invalid`。畸形来源 URL 为证据缺口。日期缺失仍可做数值比较，同时明确缺口。输出保留原始输入（包括被拒绝的 URL），只应保存公开资料；分享报告前检查原始输入是否夹带凭证或个人备注。

## 身份边界

仅精确 athleteId 加辅助信息核对通过后才比较 PB。姓名的空格、全角形式可标准化；未登记的异体字只产生候选提示，不能靠姓名或模糊相似度合并。未知 ID、明显姓名/已知大学冲突会阻止比较。

大学关系来自既有出场记录及当届代表大学，并非选手永久属性。仅在输入比赛日期（缺失时为研究截止日）之后出现的所属关系不能作为确认依据。多个历史大学、未确认身份决策、缺少姓名/大学、未登记实业团名称等进入人工审核，不自动匹配。毕业选手的历史大学不能证明其比赛时所属；应由人工核对当次身份和所属。MVP 不新增所属或别名，也不把实业团冒充大学。

## 比较与去重

| 状态 | 含义 |
| --- | --- |
| new-candidate | 已确认匹配，但当前快照没有该项目 PB |
| faster-candidate / slower | 比当前快照同项目 PB 快 / 慢 |
| same-time | 毫秒数相同；并不自动等于重复赛事 |
| needs-evidence | 日期、赛事、公开来源或身份/条件等仍有缺口 |
| identity-conflict | ID 不存在，或姓名/已登记大学与 ID 冲突 |
| invalid | 项目、成绩或非空日期无效（含晚于截止日） |
| duplicate | 重复输入行，或已匹配同场同项目同成绩同精度；保留行并列出参照 |
| multiple-results | 同选手、项目、日期、赛事标签出现不同成绩/精度；需核对预赛决赛、修订、计时口径 |

状态可以组合。每行独立与**原数据库快照**比较，不把前面的候选当作新 PB。重复和同场冲突不会删行或自动取最小值。

同场仅按 ISO 日期及去空格/NFKC/大小写标准化的赛事标签判断，不能证明官方赛事身份；不同官方名称可能漏报，重名赛事可能误报，须人工核实。不同日期的同成绩不是重复。精度不同不会直接合并。

已有 PB 在研究截止日之后时，不伪造历史快照：停止该行比较并提示。已知室内 PB 或已有“无已核实成绩”备注时，仍显式报告条件/事实冲突，不静默覆盖。CSV 没有室内外、正式资格等完整字段，因此数值比较始终只是候选。

## 两份报告

- `review.json`：原始输入、逻辑行号/起始物理行、匹配 ID/候选与理由、完整既有 PB、标准化新成绩和精度、比较/同场判断、来源与已有 sourceId、证据缺口、重复参照、相关行、`needsManualReview: true`。包含 `asOf`、输入字节 SHA-256 与本地数据快照 SHA-256，便于重现；哈希不代表来源真实性。
- `review.md`：选手/项目/既有成绩/输入成绩/判断表、逐行日期/赛事/来源与缺口、统计与审核边界。输入按文本转义，不生成主动 HTML。

统计按行计数，状态可重叠，不能相加成总人数。`matched` 是身份核对通过的行数（即便时间无效）；`duplicates` 是标记重复的行数，包括与已有 PB 重复，以及同输入组后续的重复行。`faster`/`newCandidates` 仍可能带 `needs-evidence`，并非可发布数。

所有行都要人工检查：身份与当届所属、正式比赛距离、精度/室内外/参考资格、日期/赛事一致性、来源采用版本、是否有更新更快成绩。登记 sourceId 不证明本条成绩；工具不代替 research:validate、research:complete 或独立事实复核。

## 实现与测试

纯解析 `lib/pb-csv.ts` → 纯比较 `lib/pb-preview.ts` → 报告 `lib/pb-preview-report.ts`；CLI 只读生产快照，先复用现有数据/档案校验。共享 `lib/performance-time.ts` 同时供研究审计使用，既有带分号赛事说明的 v2 成绩文本仍由研究审计提取首段。生产 Schema、稳定 ID、来源和研究日志均不变。

```bash
node --experimental-strip-types --test tests/pb-preview.test.ts tests/research-v2.test.ts
npm run research:validate
npm run data:validate
npm run typecheck
npm run lint
npm test
npm run build
npm run test:e2e
```

测试用合成选手和成绩覆盖比较、半马/场地格式、精度、日期边界、同名、身份冲突、未确认变体/转学、缺证据、重复及同场多成绩。真实 CLI 测试前后校验整个 `data/` 文件树的哈希，验证无生产写入；不依赖真实选手的硬编码 PB。
