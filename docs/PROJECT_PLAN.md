# 日本大学驿传数据库项目计划

## 1. 项目目标

建设一个可检索、可追溯的日本大学驿传数据网站，面向赛事爱好者、研究者及数据整理者。

- 整理赛事、届次、大学、选手、参赛队伍和区间成绩之间的关系。
- 支持按赛事、年份、大学和选手查询，展示总成绩、区间成绩与历史记录。
- 首期优先考虑箱根驿传、全日本大学驿传及出云驿传；实际数据覆盖以来源可用性为准。
- 为每批数据保留来源链接、采集日期和修订记录，区分官方成绩与人工整理内容。
- 优先保证数据准确性、日文姓名显示、移动端可读性及后续维护便利性。

## 4. 数据设计原则

初步实体包括大学（University）、选手（Athlete）、赛事（Event）、届次（Edition）、区间（Stage）、参赛队伍（TeamEntry）、区间成绩（StageResult）及数据来源（Source）。

- 使用稳定 ID，日文原名与别名分别保存，避免依靠姓名或校名直接关联。
- 区间成绩关联届次、区间、参赛队伍和选手；选手所属大学及年级记录在对应参赛记录中，避免覆盖历史。
- 用整数保存耗时（按来源精度采用毫秒），展示时格式化；距离统一使用米。
- 单独记录弃权、失格、未出场等状态，缺失成绩不以零代替。
- 明确赛事年份、举办日期和赛季口径，日期按日本当地赛事日历记录。
- 导入时检查重复记录、关联完整性及总成绩与区间成绩的一致性，并保留原始来源。
- 数据采集前确认来源使用条件、访问限制与署名要求，不在本阶段执行采集。

## 5. 后续 GitHub Actions 部署规划

本节只描述未来流程，本次不创建任何自动部署配置。

1. 功能分支提交拉取请求，执行依赖安装、静态检查、必要测试及构建。
2. 合并到 `main` 后，由 GitHub Actions 构建带提交 SHA 标签的容器镜像并推送至 GitHub Container Registry。
3. 配置生产 Environment 和最小权限部署凭据；服务器地址、部署密钥及数据库密码通过适当的 Secrets 或服务器配置管理，不进入仓库。
4. 在后续明确授权服务器操作后，配置 Ubuntu 22.04 的 Docker Compose、Nginx、HTTPS、数据库持久卷和备份。
5. 工作流经 SSH 验证服务器主机密钥后触发部署，拉取指定版本镜像；数据库迁移前备份，部署后执行健康检查。
6. 健康检查失败时恢复上一应用镜像；数据库迁移单独制定兼容与恢复方案，不将镜像回滚视为数据库回滚。

生产数据不保存在容器临时文件系统中。部署应限制并发，记录版本与结果，并在首次上线前完成一次备份恢复验证。
