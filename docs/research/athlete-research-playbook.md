# 选手与赛事资料研究手册

版本：2（本轮增量规则待独立评审；v1 已随 PR #20 合并）。适用：个人资料、PB、历史比赛、区间纪录、奖项和统计。入口：[AGENTS.md](../../AGENTS.md)。生产字段、时间精度沿用[选手契约](../athlete-pb-phase1.md)，本手册不替代既有校验器。

## 1. 开始前

确认任务分支、工作区修改和允许写入范围；列出稳定 athleteId、姓名/已登记别名、待研究字段、截至日期及历史所属。身份未确认时保留独立候选和审核原因，不改 ID。阅读来源目录、回归案例与日志契约；历史成绩另读导入/修订文档，奖项及纪录另读认定口径。

先核查具体来源的访问与使用条件。只整理独立表达的客观事实及定位，不转载页面、PDF、图片、解说和版式，不记录凭证。不得将其他站点的条款直接套用到本来源，也不得把公开可访问解释为书面授权。遇到明确自动访问限制就停止该方式，寻找独立允许的资料或标记人工处理，不绕过限制。政策核查与实际采用依据写入 Source.usage；没有许可依据时 permissionReference 保持 null。

## 2. 分层来源：先发现，再比较证据

| 顺序 | 必查范围 | 不能省略的后续动作 |
| --- | --- | --- |
| 1 大学官方 | 大学官网、田径/竞走部、选手档案、历代排行榜、比赛结果、历史公告、归档 PDF | 不能只访问首页或现役名册；进入具体项目榜单和对应年份结果 |
| 2 实业团官方 | 毕业选手当前实业团档案、历史比赛报告、队伍纪录与年度成绩 | 大学档案下线不构成停止理由；核实毕业后是否更新成绩 |
| 3 赛事官方 | 主办方正式结果/PDF、日本田联、地方陆协、学生联盟、关东学连、官方历史系统 | 查赛事标题、比赛日、实际项目、结果行与修订版；不要把报名表当最终成绩 |
| 4 可靠数据库 | World Athletics 及已核实数据库 | 检查身份、PB/SB、室内/室外、具体比赛；WA 未收录不否定正式成绩 |
| 5 专业媒体 | 月陸Online、体育报纸、可追溯赛事报道 | 用于线索和补证；尽可能追溯原始结果，不以媒体复述当成独立第二来源 |

优先级不是裁决顺序。旧大学 PB 与新实业团正式成绩可能是时间差，不是真正冲突。大学排行榜可能仅统计在校期间、前十名或日本籍选手。尽量使用两个独立来源；明确、完整的一手成绩可提交评审，不人为要求所有成绩先进入 WA。单一来源及尚未取得的交叉证据须明示。

## 3. 每人、每字段的三个阶段

### 发现候选（discovery）

从上述适用层级收集候选值；每个候选记录 URL、栏目/行、成绩原始写法及日期线索；正式采用 PB 时用 v2 performances 明确原候选、取得日、后续更快候选及采用/排除理由。个人资料核查姓名、大学/实业团、年级或出生日期的关联证据。字段未载明、未上榜、页面失效都是检索结果，不是“没有成绩”。

### 反向检索（reverse）

已知成绩而缺日期或赛事时，实际尝试“姓名 + 精确成绩”，日文与罗马字，以及 `28:31.87`、`28分31秒87`、`28'31\"87` 等写法；记录实际用过的词，不把建议词当已执行。进入主办方 PDF、对应年份正式结果、学校/实业团历史结果。使用确切姓名、所属及年级消歧，不仅靠罗马字同名。

出生日期/高中等没有用时的字段，反向检索候选值加姓名/所属，核查毕业名单或官方介绍，不强迫填无关成绩搜索词。资料已经齐全时，本阶段仍核对其来源链；如某路径不适用或受限，真实记录原因，不捏造访问。

### 最终核验（verification）

逐项核对并留下定位：

- 身份、当届所属和年级连续性；官方姓名异体字留在证据中，不自动合并。
- 距离：场地 5000m/10000m、公路 5km/10km、半马 21.0975km 不可混用；驿传区间不是 PB 换算来源。
- 日期取实际比赛日，不取网页发布日期；届数读取赛事标题，不由年份简单加减。跨两日比赛具体到项目比赛日。
- 原始精度：百分秒保存毫秒整数及 centisecond，整秒使用 second；不补造小数。
- 室内明确标记 indoor；确认官方有效成绩、计时口径，半马不得擅用净计时替代规定的正式成绩。
- 查询已知候选之后至核查截止日的大学/实业团年度结果、官方 PB 栏和赛事资料，检查更快成绩；当前 PB 与历史时点 PB 分开记录。历史 PB 只比较截至该时点的成绩，不用未来成绩覆盖。
- 修订/失格/参考资格、同秒/并列、路线版本：采用有效官方版本。区间赏/新/平是不同认定，不能从本站最短时间自动推出。出云第35回采用 2024-02 修订版；箱根综合与现场通过顺序不得混用。

完成三个阶段、满足证据要求后才能给出已核实结论。访问受阻或截止本轮时证据仍不足，可以结束本轮但必须保留未核实状态；不要求无限搜索。

## 4. 五种结论与停止条件

| 日志状态 | 含义及停止条件 | 禁止的推断 |
| --- | --- | --- |
| verified | 值、身份、赛事/日期及适用范围已核实；完成三个阶段，登记 Source 与定位，待独立复核 | 有一个快成绩就宣称绝对最新 |
| verified-absent | 仅适用于 PB：存在直接、明确、限定截至日期与范围的官方无正式成绩说明等肯定证据，并独立复核 | 数据库空白、未上榜、搜索无命中就判无成绩 |
| candidate | 找到候选，但日期/赛事/身份/来源登记/更新检查等不足 | 把未发布候选当正式 PB |
| not-found | 按适用层级检索后仍未找到候选；留下实际查询、受阻入口与下一步 | 认为该运动员从未跑过该项目 |
| conflict | 来源相互冲突且不能以时间/项目/版本解释，等待人工复核 | 静默选较快数或权威标签更大的来源 |

不要将后三种压成“没有成绩”。`verified-absent` 的肯定证据必须写入 final 的来源、定位与版本；个人口头判断不可自动变成新一手来源。PR #18 旧 absentEvents 保持原样，今后新增/改动该事实需新日志和证据评审，不在本 PR 追改历史数据。

## 5. 交付、验证和独立复核

研究执行者按 [v2 证据契约](audit-v2.md) 在 `data/research/batches/<batchId>.json` 保存实际过程（[字段说明](audit-log.md)）；只记录摘要，不保存网页全文。候选来源可仅登记 URL，最终采用须指向现有 Source ID；新增 Source 和正式事实应在各自数据 PR 中一同提交。

运行 research:validate、data:validate、Node、类型检查、Lint、构建及 E2E。生产原始成绩、身份和来源不得被日志工具改写。PR 列出新增事实、未核实字段、修订/冲突、实际覆盖、回归案例评估和规则建议，并逐项填写[资料审核清单](audit-log.md#pr-资料审核清单逐事实填写)，建立每项生产事实到 batchId / athleteId / field / scope 的对应关系。

独立复核者（另一位维护者/研究者，不能由执行者自批）重新打开关键一手来源，检查身份、最新候选、时间/距离/赛事届数、空缺分类；每批核查所有新增/更改事实，并用适用回归案例检查检索能力。规则变更按[改进流程](lessons-learned.md)单列评审。CI 不联网，不能证明网页已访问、来源内容支持断言或 PB 最新；不得用测试通过替代复核。

## 6. 本轮新增的执行要求

- 更新检查不再仅靠 checked=true：记录真实后续检查范围、查询索引、来源证据和取舍。毕业者查当前实业团与大学后续结果；在校者明确实业团不适用。某源受阻就如实写 blocked，不能伪造完成状态。
- 每个来源独立定位，并标它支持值、比赛日、赛事届数、距离或身份中的哪些字段；主来源定位不混写另一来源内容。
- 同一原始内容的转载共用谱系，不以两个网址当两份独立证据。单一来源、原件缺失与冲突分别报告，单一来源并非禁止提交。
- 小型赛事目录仅作明确 ID/URL 的元数据核对；未确认届数留 null，禁止按年份推算。
- ChatGPT/维护者独立联网验收事实；Codex 维护框架与合成错误测试；DSH 负责实际检索、录入和真实日志。本框架 PR 不批准下一批导入。
